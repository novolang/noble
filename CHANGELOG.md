# Changelog

Every published version, newest first. This file is on the publish

## Unreleased

`noble`: `uart_adapter()` makes an `Adapter` over `UartHci` with the default policy and RAM bonds, as the Host API sketch spells it (section 3.5).  The compiler of 0.23.2 builds a generic struct that a plain function makes.  A comment in `hci_transport.nv` calls the per-task wait flag a waker.

`noble`: a list of services, dispatched by the Adapter (planning/NOBLE-HOST-API-SKETCH.md, section 3.18, the form the owner approved on 2026-11-08).  A product makes `[dyn Service]` once at start-up and hands it to `ble.plug(var services)`, which attaches each service in order and records the first and last attribute handle it added.  `ble.pump(wait_ms)` is one turn: `AttrRead`, `AttrWrite`, `Written` and `Subscribed` go to the one service whose handles hold the attribute and are refused at once (`ATT_READ_NOT_PERMITTED` or `ATT_WRITE_NOT_PERMITTED`) when none does; `Ready`, `Connected`, `Disconnected`, `ParamsUpdated`, `SecurityChanged` and `DatabaseChanged` go to every service; any other event goes to the services until one takes it; then every `tick` runs and the `Outbox` is applied.  `ble.plug_module(var module)` attaches one service the product holds itself, with no routing, for a policy that serves it through `bind_function` (example 7).  `Service.attach` answers a `Status`; `plug`, `pump` and `serve` are methods of the Adapter.  The owner table is two fields of the Adapter, `owner_first` and `owner_last`.  New key `max_services` (default 4, 1 to 16): the size of the owner table, 48 B at the default; `budget.nv` counts it in the Host total.  New `access_from_gatt` reads a `gatt_server.Access` as an `Access`.

`noble`: `HostPolicy` gains `on_start(var self) -> Action` (default `Stay`) and `keep_serving(self) -> Bool` (default true), and `Action` gains `Advertise(set, params, data, scan_rsp)`, the arguments of `adv_start`.  `ble.serve(wait_ms) -> Status` calls `start`, asks `on_start` once and applies an `Advertise`, turns `pump` while `keep_serving` answers true, and answers the `Status` that ended it.  A value of `Action` takes about 100 B on the stack where it took 16 (two `AdData` of `max_adv_data` octets and the parameters; the size rule, not measured as a stack figure); `Advertise` is read at `on_start` only, and a link hook that answers it is read as `Stay`.  `start` stays public for a product that wants something between the start and the loop.

`noble`, `host_api`: found on the bench with the SoftDevice Controller (2026-11-08).  `Start` now handles a Controller with no public address: Read BD_ADDR answers six zero octets, and LE Set Scan Enable, and with it every use of the public address type, was refused with Invalid HCI Command Parameters.  The Host draws a third random number, makes a static random address of it (two most significant bits set), sends LE Set Random Address, and uses the random address type from then on; a Controller with a public address is brought up as before.  `Status.name()` names the Host's own failures (`timeout`, `busy`, `no room`, `link lost` and the rest) and the HCI statuses `unknown hci command`, `unknown connection identifier`, `connection limit exceeded`, `command disallowed`, `unsupported feature or parameter value` and `invalid hci command parameters` (constants `HCI_UNKNOWN_COMMAND`, `HCI_UNKNOWN_CONNECTION`, `HCI_CONNECTION_LIMIT_EXCEEDED`, `HCI_COMMAND_DISALLOWED`, `HCI_UNSUPPORTED_PARAMETER`, `HCI_INVALID_PARAMETERS`), where it answered "unknown" for them.  `noble.Host` is the name of `host.Host`: a program or a service module writes `var h: noble.Host` (the alias was refused as a cycle until the compiler of 0.23.2).

`noble`, `host_api`: the Host API, Layer B, the Adapter and the calls that wait (planning/NOBLE-HOST-API-SKETCH.md sections 3.5, 3.6, 3.10 and 3.13).  `noble.adapter(link, policy, bonds)` holds a `Host`, the transport, the policy and the bond store; `step`, `run`, `start` and `wait_event` turn the Host and park in `HciLink.park` between turns, and every call answers a `Status` and ends with `E_TIMEOUT` when the Controller is silent.  GAP: `adv_start` (legacy and extended), `periodic_start`, `adv_stop`, `scan_start` with a `ScanFilter` (a service, a name prefix, a signal floor), `scan_stop`, `find`, `sync_create`, `sync_stop`, `accept_list_from_bonds`, and the policy's `Action.Readvertise`, which restarts the last advertising; `ad_flags`, `ad_uuid16`, `ad_name`, `adv_legacy`, `scan_all`, `scan_service`, `scan_passive` make the payloads and parameters.  GATT client: `exchange_mtu`, `discover`, `find_char`, `read`, `write`, `write_no_response`, `subscribe`, `unsubscribe` over the client engine of the Host, with a `need` that refuses a request below it with `E_SECURITY_LOW` before anything is sent.  GATT server: `add_service`, `add_char`, `set_value`, `bind_function` (a read or write calls `HostPolicy.on_read` or `on_write` with the index of the owning service), `bind_event` (the request is queued as `Event.AttrRead` or `AttrWrite` and answered with `respond`), `notify`, `notify_all`, `indicate`.  The events `Notification`, `Subscribed`, `AttrRead`, `AttrWrite` and `DatabaseChanged` are queued, and `Written` for every stored characteristic.  Services: the trait `Service`, `Out` and `Outbox`, with `plug` and `pump` as the first entry of this section states them (attribute requests as events, answered through the `Outbox`).  `UartHci` is H4 over `hal.uart`.  Two keys: `max_name` (24) and `outbox` (4), both sizes of values on the caller's stack.  NOT IMPLEMENTED: `HostPolicy.authorize_write`, bound attributes on an Enhanced ATT bearer, extended scan reports, periodic advertising reports, and the use of `BondStore.load_server` and `load_cache`.

`gatt_server`: `GattDb.bound` and `AttLink.held` hold the requests for the attributes the application binds (`bind`, `bound_mode`, `bound_service`, `take_held`); the server checks the access and the format of the request first.  `value_of_configuration` names the value of a Client Characteristic Configuration descriptor.  `host`: `Host` gains `add_service`, `add_char`, `bind_function`, `bind_event` and `set_value`.

`noble`, `host_api`: the Host API, Layer A, the request-and-poll core of the application surface (planning/NOBLE-HOST-API-SKETCH.md sections 3.3 and 3.4).  An application holds a `Host` and calls `begin(var h, req)`, `poll(var h, var t, var p, var b, now_ms)`, `result(var h)` and `next_event(var h)`; nothing in them waits, reads a clock or sleeps.  `Status` carries the layer and the code of a failure, with the names of ATT, HCI and SMP (`ATT_INSUFFICIENT_AUTHENTICATION`, `HCI_CONNECTION_TIMEOUT`, `SMP_PASSKEY_ENTRY_FAILED`) and the Host's own (`E_BUSY`, `E_STALE`, `E_REFUSED`), and `from_client_status`, `from_client_error`, `from_advertiser_error`, `from_smp_reason` and `from_profile_error` read the five older error forms as one.  `ConnId` is a slot and its generation, so a name kept after a link ended is refused with `E_STALE`.  `HostPolicy` holds the decisions of the product (`accept_connect`, `accept_pairing`, `ask_passkey`, `confirm_numeric`, `accept_params`, `on_connected`, `on_disconnected` and the rest), each with a default; `BondStore` and `RamBonds` hold the keys.  Events are queued, with a slot kept for each connection's state events; an advert or a notification that does not fit is dropped and counted in `Event.Dropped`.  The engine serves `Start`, `Connect`, `ConnectListed`, `ConnectCancel`, `Disconnect`, `UpdateParams`, `Secure`, `CocOpen` and `CocClose`, with `passkey_reply`, `numeric_reply`, `unbond`, `coc_listen` and `coc_send`; advertising, scanning, synchronization and the GATT client requests were NOT IMPLEMENTED in it and `begin` answered them `E_BAD_ARGUMENT`; Layer B below serves them.

Configuration: three keys, `event_queue` (0 in the default, so a Host that does not use the API pays for no queue), `att_value_bytes` (64) and `max_adv_data` (31).  `configs/layer_a.toml` gives the tests of the API four events.

`hci_transport`: `HciLink.send_packet` takes `var self`, as `recv_packet` does, so a link can keep what it sent; `HciLink` gains `now_ms` and `park`, each with a default (the system tick and a yield).  An impl that wrote `send_packet(self, ...)` writes `send_packet(var self, ...)`.

`host`: `Host` carries the state of the API (`api`, `acl_out`, `cmd_wait`), and `host_seed` gives the Security Manager its seed and key pair; the BTP session of `orbit/ble` calls it.

`host`: the Host as one value.  `Host` holds the 29 fields of the Bluetooth Test Protocol session of `orbit/ble` that are Host state and not the state of a test service (the link registry and active `LeLink`, the parked per-connection state, the Security Manager halves, the bonds, the pairing settings, the GATT client table, the queue of commands owed to the Controller and the rest), `host_blank(host_config(slots, name))` makes one, and `host_activate` switches the connection the per-connection fields describe.  Two Hosts in one program share no table.  `SecuritySettings`, `LinkSession` and the Appearance, Peripheral Preferred Connection Parameters and bond-capacity constants moved here from `orbit/ble/src/btp/btp_session.nv` with no change.

`cs_gap`: the Channel Sounding GAP procedures of Core Vol 3 Part C, Sections 9.7 and 10.11.1, as an engine that a program drives with `cs_gap_next`, `cs_gap_event`, `cs_gap_tick` and `cs_gap_take_result`: the capabilities of both Controllers, the default settings, the security start, the remote FAE table, the configuration, the procedure parameters and Procedure Enable, then the result events of each procedure joined into one `HciCsProcResult`.  Either ACL role and either CS role; the security levels 1 to 4 choose the configuration and the requirements.

## 0.1.0

First release.  The Host core of the noble Bluetooth stack, extracted from
`orbit/ble`: the HCI session and transports, the link table, L2CAP and the
credit based channels, ATT, the GATT server and client, GAP and the
advertisers, the Security Manager and bonding, privacy, and the isochronous
transport.  The HCI wire is read through `noble-hci`.

The 38 keys of the `orbit/ble` configuration that size the Host core are the
schema of this package, under the section `[noble]`; the constants are read as
`noble_config.MAX_*`.  Twelve keys of the audio roles and the services stay in
this schema because their cost formulas multiply a key of the core.

The public surface is what an extension module, a chip image and a PC Host call:
the ATT and GATT server and client, the links and the HCI session, the credit
based channels, the Security Manager, the advertisers, the isochronous tables,
and the encodings and builders the services share.  The unit tests are the
suites `tests/<module>_tests.nv`, which run under the smallest and the largest
configuration and under each file of `configs/`.
